# R001 G1-P2 隔离探针误访生产 API 事故记录

> 状态：已记录（RECORDED）。只读复核完成；未清理审计、未重置账号。
> 记录时间：2026-11-12（UTC）

## 一、事实经过

- G1-P2-RC1 隔离复现阶段，在 u-dao 服务器本地搭建测试栈（compose.test.yml，
  默认 TEST_HTTP_PORT=18080）。
- 生产 firebot nginx 自 10-27 起已发布 `127.0.0.1:18080:80`（调试回环入口），
  与测试栈端口同名冲突。测试 nginx 未获得该端口发布，探针流量实际进入**生产 nginx →
  生产 API**。
- 我的登录探针（playwright/curl/python，共 4 次 POST /api/v1/auth/login，
  测试口令对生产 admin 无效）因此打到生产 API，产生：
  - 4 条 `AUTH_LOGIN / result=FAILED` 审计（生产 audit_logs，2026-11-12T03:19Z 前后）
  - 生产 `users.admin.failed_attempts` 由 0 → 4
- 未触发锁定：生产登录限 5 次，`locked_until` 保持 NULL；账号 status 仍 ACTIVE。

## 二、影响与澄清

1. **澄清（重要）**：Redis `login-fail:{ip}:{user}` 计数器 300 秒过期
   **不等于**数据库 `failed_attempts` 自动清零。DB 计数仅在**成功登录**时归零；
   生产 admin 自 2026-10-28 后无人登录，故 failed_attempts=4 持续存在，
   且生产 Redis 侧计数已过期 → 下一次失败登录会再次从 1 计数（不会立即锁定）。
2. 除上述审计行与 failed_attempts 计数外，无任何配置/服务/数据变更；
   探针均为只读 GET + 失败登录，未获取任何会话。
3. 复现排障期间发现后立即停止 18080 探针，测试栈改用 28080 端口。

## 三、复核结论（只读，2026-11-12T03:5xZ）

- admin：status=ACTIVE、failed_attempts=4、locked_until=NULL、last_login_at 未变。
- AUTH_LOGIN FAILED 审计共 6 条（其中 2 条为 10-28 历史，4 条为本事故新增）。
- 未执行任何清理/重置操作。

## 四、防再发措施（已实施）

1. `apps/web/e2e/helpers/auth.ts` 新增 `assertTestTarget`：任何 E2E 探针在登录成功后、
   任何变更前，必须验证目标服务的机器人列表包含测试种子名称
   （`灭火机器人 R001/R002`），否则立即中止——**判定依据是数据特征而非端口**。
2. 本地测试端口改用 28080；正式模板（deploy/u-dao/r001-independent）公网端口 8884
   为独立规划端口，不与生产回环端口重叠。
3. 本记录随仓库版本固化，供发布审计引用。
