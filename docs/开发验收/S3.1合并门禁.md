# S3.1 Merge Gate Hardening

本轮只修复应用回滚和 npm Critical 分类，不增加 Vehicle Agent/HMI 功能。

显式回滚与失败发布自动回滚共用 `rollback_to`。它先按 Compose project/service 标签找到并停止、移除当前 adapter，再切换到 previous SHA，从目标 Compose 读取实际服务集合。pre-adapter 目标只重建五个核心应用服务，并检查 adapter 已不存在；post-adapter 目标重建其旧版 adapter。所有重建服务检查 health 和精确 image revision。清理失败、残留 adapter、无法读取 Compose 或 project 不匹配均返回失败，不报告回滚成功。应用回滚不执行 alembic downgrade，additive 0009 保留。

`python scripts/test_server_rollback.py` 使用 Git/Docker 命令替身运行两条实际 caller，覆盖 pre/post adapter，以及 stop/remove 失败和假成功残留。两个 previous Compose 直接读取不可变历史：584efcfda60b8d39c516a9939bc0481609fc6f3c（无 adapter）与 f8bb20e9d0e192f814265a0a671b3be3a077c34d（含 adapter）。不修改历史提交，不连接生产。docs CI 获取完整历史并运行该回归。

前端 CI 执行 `node scripts/audit_web_dependencies.cjs`（从仓库根执行；CI 使用相应相对路径）。门禁运行 `npm audit --omit=dev --audit-level=critical --json`，显式输出 `NPM_PRODUCTION_CRITICAL_COUNT`，只在计数为 0 且 npm 门禁成功时输出 PASS；网络失败、无效审计数据也拒绝通过。同时保留 full audit JSON，上传 `npm-audit-classification` artifact。没有修改依赖版本、强制修复或降低原 Trivy gate。

2026-10-22 本地分类：production Critical=0、HIGH=6；full audit Critical=2、HIGH=17、moderate=3，共 22 项。两项 Critical 来自开发测试链路的 tinypool/Vitest，生产审计不包含它们。这不代表完整 npm 风险已经清零。

后续维护项：单独评估 tinypool/Vitest 的兼容升级，处理开发链路 Critical 以及 production/full audit 的 HIGH；本轮不执行 Vue/Vite/TypeScript 等大范围升级。最终计数与完整 CI 证据见本轮验收报告及 audit artifact。
