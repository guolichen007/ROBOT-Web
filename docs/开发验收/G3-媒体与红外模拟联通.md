# G3：媒体 RGB/thermal 与红外模拟数值联通（隔离环境）

基线：G2 冻结 `43d76f47332a949df386341642e9defdf0321f6e`（本分支在其上增量，不改动 G2 命令路由）。

## 1. 媒体（复用现有 MediaMTX + media-test-source，不新建媒体服务器）

- 合成源 `services/media-test-source`：新增 `SIMULATED_LABEL` / `SIMULATED_KIND`——顶部红色
  “SIMULATED <RGB|THERMAL>” 横幅 + 时间戳；thermal 使用伪彩（inferno）。
- RTSP 车辆身份发布：`RTSP_USER=<vehicle_id>`（password=该车 HMAC 派生 token）；
  `SRT_USER=""` 表示合成流（全局合成 token）。
- 合成流登记：`StreamRegistry.source_ref = "SYNTHETIC_TEST"`（无迁移，复用既有列）。

## 2. 发布鉴权（/api/v1/media/authorize）

| 流类型 | 唯一允许的发布凭据 |
| --- | --- |
| 合成测试流（source_ref=SYNTHETIC_TEST） | 全局合成 token（token 字段或 user 为空时的 password）；车辆凭证拒绝 |
| 真实车辆流（其他） | user == 流所属 vehicle_id 且 password == 该车 HMAC 派生 token；全局 token 拒绝 |

拒绝写审计日志 `media publish denied`（仅 stream_id 与原因，不含任何凭据/URL）。
**兼容影响**：旧做法“全局 token 发布 R001-roof_rgb”被拒；`compose.test.yml` 的 media-test-source
已改为以 R001 车辆身份（测试专用派生值）发布。生产 `compose.media-e2e.yml` 本就使用 R001 派生 token。

## 3. 红外数值（V1 telemetry.thermal.max_temp，不新增协议）

- 模拟源 `services/ir_telemetry_sim`：身份固定 `firebot-sim-ir-01`（其余 ID 退出码 2），复用只读
  Agent 的 TLS/凭证/零订阅 transport。
- 合同收紧：`max_temp` 严格数值（拒绝字符串/布尔隐式转换），量程 −50…1200 ℃。
- Ingress：遥测只有在新鲜（−2s…stale 门限）、非 retained、且不早于当前实时值时才更新实时
  telemetry / Redis latest.top_ir / SensorSample；否则记录 `v1 telemetry not applied as live`。
- 模拟标识：`SIMULATED_VEHICLE_IDS`（默认 `firebot-sim-ir-01`）→ snapshot `simulation` 字段 →
  Web “SIMULATED · 模拟数据源”横幅与“温度（模拟）”。不从 `source_kind=MOCK` 推断。

## 4. 控制边界

相机 PTZ / NUC / 测温模式不在 V1 命令集，API 返回 UNKNOWN_COMMAND；本轮仅验证 Web 连接/断开
（WHEP POST/DELETE）、合成发布进程启停、断流后重新发布恢复、G2 软件指令 ACK（G2 E2E 回归）。

## 5. 回滚

纯应用层改动、无迁移：回退到 G2 冻结镜像（43d76f4）即可；若仅需撤销媒体鉴权收紧，回退
`apps/api/app/modules/media/router.py`。模拟源/合成流仅在隔离环境登记，生产无对应数据。
