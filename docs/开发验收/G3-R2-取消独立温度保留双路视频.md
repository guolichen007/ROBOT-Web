# G3-R2：取消独立温度功能，保留双路实时视频（硬件需求变更合同）

状态：**生效**（OWNER 硬件需求变更，2026-11-17）。基线 `feature/g2-g3-integration` @ `fee5e55`。
本文件是本次变更的唯一产品契约，同时承担 PRD 变更记录、硬件清单变更、G3/G4 验收合同温度条款、
公网 Preview 说明与车端交接说明。原 [G3-媒体与红外模拟联通](G3-媒体与红外模拟联通.md) 中的“红外数值”章节以本文件为准。

## 1. 一句话契约

| 能力 | 结论 |
| --- | --- |
| 热成像**视频**（`roof_thermal`） | **保留**：首页与 RGB 可见光（`roof_rgb`）双路实时视频同时显示 |
| 红外**温度数值**（独立测温传感器 / `max_temp` / `top_ir` / `bottom_ir`） | **停用**：不采集、不模拟发送、不在产品中展示 |
| 从热成像画面推算温度 | **禁止**：不推算、不伪造任何温度数值 |

## 2. PRD 变更（产品界面）

- 首页指标固定四项：**智能车状态 / 电池 / 烟雾 / 通信状态·接收延迟**。删除“温度 / 温度（模拟）”卡片，
  不显示“未知”“0℃”“--℃”等任何温度占位；即使云端收到历史或兼容温度数据也不显示。
- 桌面（≥1101px）四项单行等宽；≤1100px（平板 / 手机）2×2；不产生横向滚动。
- 双路视频保留：`roof_rgb`（标题“监控相机”）+ `roof_thermal`（标题“红外热成像”），同时挂载，
  切换控制 Tab 不卸载；地图、车辆控制区布局不变。模拟源继续显示 `SIMULATED` 横幅 / 画面水印。
- 顶栏（非监控页）删除“顶部热像 / 底部红外”温度数值格；设备详情“数据接入”删除“上红外 / 下红外”
  测温通道行，保留“顶部热成像视频”（`roof_thermal`）通道行。
- 历史页本就无温度曲线；系统未配置温度阈值。**审计结论：仓库内不存在任何基于温度的自动安全联锁**
  （云端 / Web / 车端 Bridge 均无温度阈值判断），无需单独解除。

## 3. 硬件清单变更

| 项 | 变更前 | 变更后 |
| --- | --- | --- |
| RGB 可见光相机 | 配置 | **配置（不变）** |
| 热成像相机（视频） | 配置 | **配置（不变）** |
| 独立红外测温传感器（数值） | 计划配置 | **不配置** |

无独立温度数值来源。车端 Agent 现有行为不变：未接入硬件时 `telemetry.thermal=null`（显式空，不伪造）。

## 4. 后端兼容性（不做破坏性变更）

- 保留：V1 `telemetry.thermal.max_temp` 合同与校验（严格数值 −50…1200）、1.3 `sensor.top_ir_max/bottom_ir`、
  `SensorSample.top_ir_max/bottom_ir` 列、Redis `latest.top_ir`、API snapshot `top_ir` 字段与历史数据。
  **无迁移**、无字段删除；历史数据原样保留。
- 停用：`services/ir_telemetry_sim` 默认退出码 3（在读取身份 / 连接 Broker 之前），仅在
  `FIREBOT_LEGACY_THERMAL_COMPAT_TEST=1` **且** `--legacy-compat-test` 时运行，用途限于兼容性测试。
  仓库内无任何部署 / compose / systemd 入口启动它；当前产品运行不依赖它。
- 模拟设备在线：新增 `services/sim_presence`——独立模拟身份（`firebot-sim-<name>`，拒绝 R001/R002/
  firebot-vehicle-*）只上报 `availability` / `status`，**结构上不发送 telemetry**（单测以“调用即失败”反证）。
- 不变：thermal 视频（StreamRegistry `roof_thermal`、媒体鉴权、MediaMTX、VideoCard）、MQTT 通信、
  G1/G2 命令机制、R002 协议与运行行为。

## 5. G3 / G4 验收合同（温度条款替换）

原 G3 Web 温度展示验收（27.5 / 42.0 / 67.8 / null 在 PG/Redis/API/Web 一致、null 显示“未知”）**作废**，替换为：

| 编号 | 验收项 | 证据位置 |
| --- | --- | --- |
| T1 | 无温度传感器时首页无温度卡片，四项指标 | `test_no_temperature_card_without_sensor_and_with_legacy_data`、Vitest |
| T2 | 收到历史/兼容温度数据（67.8 进入 PG/Redis/API）时 Web 仍无温度卡片、页面无“67.8/温度/℃” | 同上 |
| T3 | 产品路径不发送任何温度遥测（sim_presence 前后 SensorSample 计数不变） | 同上、`test_presence_reports_online_without_any_telemetry` |
| T4 | 温度模拟器默认停用（缺任一开关退出码 3，零写入） | `test_temperature_simulator_disabled_by_default`、`test_g3r2_temperature_disabled.py` |
| V1 | RGB 与 thermal 两路生产 VideoCard 真实解码、帧变化、`SIMULATED` 标识 | `test_production_videocard_rgb_and_thermal_decode` |
| V2 | 首帧门控（“实时”只在首个解码帧后出现） | 同上 gate 断言 |
| V3 | 双路连续 60s（每秒有新帧、始终实时） | `test_dual_stream_60s_continuous` |
| V4 | 短断流自动恢复 / 长断流耗尽后手动恢复 | `test_stream_outage_and_reconnect_in_videocard`、`test_manual_recovery_after_long_outage` |
| V5 | 切车隔离（模拟会话 DELETE 释放、真实 001 无模拟流） | `test_vehicle_switch_releases_sim_session_and_real_001_shows_no_sim` |

原温度底层测试（采集、新鲜度、类型、幂等、身份隔离、ACL）**保留为兼容性测试**，不删除。
G4 及后续轮次如引用温度 KPI，一律以本节为准；仓库内无独立 G4 文档。

## 6. 公网 Preview 说明

- Preview / 验收环境**不得**运行 `ir_telemetry_sim`，不得设置 `FIREBOT_LEGACY_THERMAL_COMPAT_TEST`。
- 模拟设备在线如需要，使用：
  `python -m services.sim_presence.main --config <firebot-sim-*.json, 0600> --hold-seconds <秒>`；
  视频仍用 `services/media-test-source`（`SIMULATED_KIND=rgb|thermal`，逐流 HMAC 口令）。
- `SIMULATED_VEHICLE_IDS` / `SYNTHETIC_MEDIA_VEHICLE_IDS` 规则不变；生产常态 `SYNTHETIC_MEDIA_VEHICLE_IDS` 为空。
- 浏览器验收阶段：`play`（双路首帧门控 + 解码 + 首页四项 KPI）、`kpis`（只读 KPI；stdin 可加
  `"forbid_text":"67.8"`）、`dual60`、`switch`；原 `temps` 阶段已删除。

## 7. 车端交接说明

- 车端**不需要**接入或调试任何独立测温传感器；`telemetry.thermal` 保持 `null` 即符合合同。
- 若车端旧程序仍上报 `thermal.max_temp`，云端照常校验保存（兼容），Web 不展示；**不要**为此改车端。
- 热成像相机作为**视频源**照常接入：`R00N-roof_thermal`，H.264 + yuv420p，SRT 发布（见
  [车端云通信与视频链路](../部署运维/车端云通信与视频链路.md)）。不得从热成像画面导出温度数值上报。

## 8. 回滚

纯应用层变更、无迁移：回退到 `fee5e55` 即恢复温度卡片与模拟器默认可用。
