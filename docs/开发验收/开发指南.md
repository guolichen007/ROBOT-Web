# 开发规范

- 从最新 `main` 建短生命周期分支（`feature/…`、`fix/…`、`maintenance/…`、`field/…`、`release/…`），通过 PR 合入 `main`，合入后删除临时分支。
- 禁止 force push/delete `main`，禁止绕过 required checks。
- Python 执行 Ruff、format、mypy、Pytest；Web 执行 ESLint、Prettier、vue-tsc、Vitest、build。
- 协议只能修改 canonical JSON Schema，再同步生成模型、Mock、tester、integration package。
- 新业务事实必须在 PostgreSQL commit 后发布实时事件；QoS1 逻辑必须按 at-least-once 与幂等设计。
- 不得在本仓库实现 ROS2、SLAM、Nav2、车端驱动、执行机构或 watchdog。
- production 代码不允许遗留未在 allowlist 中的 TODO/FIXME/HACK。

## Windows 干净环境启动

1. 安装 Git for Windows、Docker Desktop，启用 WSL2 backend。
2. 确认 `git --version`、`docker version`、`docker compose version` 正常。
3. 使用 SSH clone：

```powershell
git clone git@github.com:guolichen007/ROBOT-Web.git C:\Users\13576\Desktop\web_robot
Set-Location C:\Users\13576\Desktop\web_robot
Copy-Item .env.example .env
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\dev.ps1
```

Web 为 `http://localhost:8080`。首次启动终端显示一次性 admin 密码，首次登录必须修改。运行测试用 `.\scripts\test.ps1`，停止用 `.\scripts\stop.ps1`。

若 8080/1883/8554/8889/9997 被占用，先用 `Get-NetTCPConnection -State Listen` 定位；不要修改 SERVER 公网暴露规则来规避端口冲突。Windows 防火墙只需允许本机开发所需端口，不应将 DEV Broker 暴露到不可信网络。

更新代码：停止 DEV、`git pull --ff-only`、重新执行 `dev.ps1`。不要提交 `.env`、`backups/`、`dist/`、证书或现场文件。

## 模拟数据上线前清理

真实上线建议使用**全新生产数据库 / 新 site**，而不是在含模拟数据的老库上做删除；历史模拟审计通过 UI 过滤「开发测试」保留可追溯性。

可靠判别器：`RobotIntegrationProfile.source_kind == "MOCK"` 的机器人，其任务/火情/遥测都是模拟数据。没有该标记的旧数据（人工上报火情、历史测试任务）无法可靠区分，**不猜测删除**。

```bash
# 在 api 的 venv 内，从仓库根目录执行
python scripts/reset_demo_data.py                    # dry-run
python scripts/reset_demo_data.py --export ./backup  # dry-run + 备份
python scripts/reset_demo_data.py --execute          # DEV 环境删除（server 需 --force-server）
```

删除顺序：识别（`source_kind=="MOCK"` + `boot_id=="seed-history"` + 明确测试 note）→ dry-run → `--export` 备份 → `--execute`（仅 `app_env=="dev"` 放行）。审计日志不删除（immutable/retention 合同）。
