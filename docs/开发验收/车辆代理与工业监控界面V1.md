# vehicle_agent 与工业监控界面 V1

本支线从 `b7062b4a3a14637ee5076b4825f6df375b1f7677` 的 main 创建。仅开发、mock 验收及推送功能支线；不合并 main、不部署生产、不进行实车联调。

## 协议边界

```text
Browser → FastAPI（鉴权 / 权限 / readiness / 幂等 / 审计）
        → Command / Task / Outbox → command-dispatcher
        → _platform/vehicle-agent-v1/{vehicle_id}/command
        → 独立 vehicle-agent-adapter → v1/robot/{vehicle_id}/cmd

vehicle_agent → v1/robot/{vehicle_id}/{availability,status,telemetry,event,ack}
              → adapter → 平台内部规范化事件 → mqtt-ingress
              → 既有 DB / Redis cache / replay stream / WebSocket → Browser
```

adapter 不导入业务数据库模型，不实现用户权限；平台内部 topic 只授权 platform。旧 canonical 1.2/1.3 schema 与生成模型保持 frozen。新增内部命令扩展使用 `schema_version=vehicle-agent-v1`，共用 Command/Outbox 和既有调度服务，不向旧车辆发送扩展命令。

合同模型见 [协议模块](../../services/vehicle_agent_v1.py)；可检查的生成合同见 [v1 合同](../../packages/protocol-schemas/vehicle-agent-v1.contract.json)。修改后运行 `python scripts/generate_vehicle_agent_contract.py`，对应单测验证生成结果没有漂移。

| topic 后缀 | QoS | retain |
| --- | ---: | --- |
| cmd | 1 | false |
| ack | 1 | false |
| status | 1 | true |
| telemetry | 0 | false |
| availability | 1 | true |
| event | 1 | false |

availability 接受字符串 `online/offline` 或带 `state` 的对象。status 接受 online、programs、task；programs 的 `true/running/ready` 表示运行或就绪，缺字段不推断为就绪。task.state 只接受 idle/patrol/homing/spot。telemetry 处理 pose（yaw 保留为角度弧度）、battery、smog、thermal；percentage 按百分数 0–100 校验，缺字段为 null。status/telemetry 的扩展元数据不授予控制能力。

event 保留为平台事件及系统审计记录；未约定火警事件载荷前，不猜测其字段并自动创建 FireEvent。既有告警流程保持不变。

## 每车唯一控制绑定

新迁移 `20261021_0009` 增加 Robot.agent_protocol / agent_state_json 和 Command.ack_payload_json。旧行默认 `CANONICAL_MQTT`，迁移不会自动启用 v1；没有改写历史 migration。

`PUT /api/v1/robots/{robot_id}/agent-protocol`，body 为 `{"protocol":"VEHICLE_AGENT_V1"}`，要求 `settings.manage`。仅允许离线、无租约、无活动任务且无待确认命令的车辆切换。切换会清除旧实时缓存/boot、重置控制/ACK/地图验证标记并写审计，不能借切换协议开启控制。

dispatcher 按 DB 绑定选择唯一的下行 topic；v1 绑定拒绝旧 canonical 下行和旧 canonical 上行，旧绑定拒绝 v1 下行及 v1 状态。adapter 发送前再检查平台写入 Redis 的协议/boot 绑定，ACK 也再次核对 DB 当前 boot。ROS_COMPAT 下行仍未实现，保持拒绝。

生产配置默认：

```dotenv
VEHICLE_AGENT_V1_DOWNLINK_ENABLED=false
VEHICLE_AGENT_V1_ACK_TIMEOUT_SECONDS=90
```

生产 Compose 的 adapter 位于显式 `vehicle-agent` profile；本支线没有启动它。即使将开关打开，仍须完成既有控制/ACK/地图/急停事实等验证。新协议不提供的 emergency_stop / manual_control 不会被映射成 close；正式 UI 保留软件急停和既有控制入口，并按对应安全合同禁用。

## 八项操作与状态收敛

统一 API：`POST /api/v1/robots/{robot_id}/agent/commands/{action}`，必须带 `Idempotency-Key`，body 为 `{"params":{...}}`，立即返回 202 的 Command。FastAPI 不等待 90 秒。

| HMI 按钮 | action | params | 权限 |
| --- | --- | --- | --- |
| 启动 | start | `{"with_navigation":true}` | robot.control.task |
| 关闭 | close | `{}` | robot.control.stop |
| 开始巡逻 | patrol | `{}` | patrol.create |
| 停止巡逻 | stop_patrol | `{}` | robot.control.stop |
| 恢复巡逻 | resume_patrol | `{}` | patrol.create |
| 返航 | homing | `{}` | robot.control.task |
| 前往目标 | navigate | `{"spot":"当前地图的车位名称"}` | robot.control.task |
| 停止目标 | stop_navigate | `{}` | robot.control.stop |

辅助 ping/get_status/get_telemetry 使用 robot.read，不作为主按钮。运动命令必须具备 chassis/navigation 就绪、地图合同、无手动租约、无冲突任务；恢复巡逻还必须 patrol_paused=true。homing、patrol、spot 互斥；运行中的 patrol 先停止为 paused 后才能恢复或关闭。服务端重新执行全部门禁，不能依赖前端 disable。

canonical message_id 直接作为 v1 UUID msg_id，Redis 持久保存 vehicle_id/msg_id → command_id/message_id/target_boot_id 的精确关联和 ACK。重试保持同一 UUID；mock 实现 300 秒去重，adapter 拒绝同一 UUID 对应不同命令。关联与终态缓存保留 24 小时，命令过期后不能重发执行。

ACK 中 ALREADY_RUNNING / ALREADY_CLOSED / ALREADY_STOPPED 按幂等成功处理；所有失败的 code/message/data/duration_ms 保存在 ack_payload_json。ACK timeout 返回 PUBLISHED_UNCONFIRMED，不将“可能已执行”伪装成失败后可随意重发，也不伪装成功；同一未确认动作及协议切换会被阻止。需通过受审计的人工核实流程处置未确认命令。

ACK_ACCEPTED 后只接受发令后的 status 共同确认。开始运动后命令/任务进入 EXECUTING。navigate 的 ACK 仅表示 goal 被接受，task.state=spot 仍为前往目标；观察到执行之后的新 idle 状态才结束任务。停止目标后任务为 CANCELLED，不能标记为到达成功。ACK 已到但 status 长时间未确认，也由 worker 转为 PUBLISHED_UNCONFIRMED。

## HMI 与离线规则

主区域为地图约 60%、双视频约 20%、控制栏约 20%。保留 MapCanvas 的 pan/zoom/pose/车位算法；地图点击和停车位 dropdown 共用 selectedSlotId。实时地图/车位地图只切换覆盖图层，不重建地图算法。

roof_rgb 与 roof_thermal 同时垂直挂载；不显示 bottom_ir 视频。右侧自动导航/手动控制/监测切换不卸载视频。既有 alarm、E-stop、readiness、STOP operation 和任务入口分别保留在全局横幅、固定安全入口及后两个 Tab。

顶部 battery/thermal/smog 来自 backend state；缺字段为 `--`。延迟为服务器计算的源 ts 到接收时刻的差值，负值/缺 ts 为 null，不伪造 RTT。车端 offline、服务器 watchdog stale/offline 或 WebSocket 断开时，历史值标记陈旧/离线。缺少有效 pose 或 frame 与地图不一致时，移除地图实时 pose 投影。

用户提供的 patch 文本落盘后 SHA256：`a77e0ced7b6af6d7020ad8661cc7971c1ede90c126231d8e32fc9e651803e49e`。

用户本机提供的原始 WHEP test SHA256：`84ae4169daa893324e1992573241015be13cee519d389b9e694aee004bb46078`。两者均与任务记录一致；patch 在最新 main 上通过 git apply --check 后导入。此后仅在该回归测试中增加重入、状态更新和中途 inactive 用例。

VideoCard 本地 PlayerState 与媒体源状态分离，连接只由用户点击触发；snapshot 和 WS 不重连。连接过程具有重入锁及 session epoch，stream_id 真变化、inactive、DISABLED 或卸载会终止旧会话，并清理迟到的 WHEP session。

Nginx 保留 `proxy_pass http://media_upstream/;`、`proxy_redirect / /media/;` 与 Authorization 转发，使 WHEP DELETE 仍经过 /media/。MediaMTX 保留 UDP/TCP :8189。Compose 的 RTSP 8554 只绑定 SERVER_TAILSCALE_IP，WebRTC 8189 只绑定 SERVER_LAN_IP；env example 仅为文档保留地址。

`KNOWN_RISK_WEBRTC_8189_TOPOLOGY=OPEN`：additionalHosts 可以包含 LAN/Tailscale，但监听拓扑尚未现场验证；本支线未扩大 8189 暴露，也未更改防火墙。视频仍是 RTSP → MediaMTX → WHEP/WebRTC，不通过 MQTT。

server-deploy.sh 与 firebotctl 已移除临时探针 dirty 豁免，exact-SHA release 要求完全 clean。本轮没有运行、导入或提交该探针。

## 自动化验收

前端在 apps/web 中执行：

```text
npm ci --ignore-scripts
npm run format:check
npm run lint
npm run typecheck
npm test
npm run build
```

后端安装 requirements-dev.txt。纯协议测试位于 services/protocol-tester/tests/test_vehicle_agent_v1.py；API mock 集成位于 apps/api/tests/test_vehicle_agent_mock_integration.py。后者使用真实鉴权、Command/Task/Outbox、dispatcher、adapter、ingress 与 WebSocket；只有 broker/Redis 和 PostgreSQL fixture 使用 fake/SQLite。SQLite fixture 不证明 PostgreSQL 分区、行锁、migration 或 MQTT TLS/ACL 的运行正确性。

浏览器隔离闭环运行方式（始终使用回环地址）：

```text
PYTHONPATH=apps/api:.
APP_ENV=test
python scripts/vehicle_agent_mock_runtime.py

# 另一个终端，在 apps/web：
FIREBOT_DEV_BACKEND=http://127.0.0.1:18765 npm run dev -- --host 127.0.0.1 --port 15173
E2E_BASE_URL=http://127.0.0.1:15173 VEHICLE_AGENT_MOCK_E2E=1 npm run test:e2e -- e2e/vehicle-agent-mock.spec.ts
```

以上为 POSIX 环境变量写法；Windows PowerShell 使用 `$env:名称='值'`，PYTHONPATH 分隔符为分号。没有浏览器包时可使用 PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH 指向本机 Chromium/Edge。测试脚本只创建临时本地 DB，绝不连接真实 broker。
