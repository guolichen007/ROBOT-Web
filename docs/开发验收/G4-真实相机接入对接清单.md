## 3. 需车端 CC 回填的设备事实

1. **Q1 相机型号 / 接口**：RGB 与热成像各是什么设备？取流方式（RTSP / ONVIF / USB-UVC / 厂商 SDK）？
2. **Q2 取流地址形态**：RTSP URL 路径格式（不要发凭据本身）、是否需要认证、主/子码流选择。
3. **Q3 原生编码**：H.264 还是 H.265？分辨率、帧率、GOP；热成像是否输出伪彩 H.264 还是原始灰度/Y16。
4. **Q4 车端算力与软件**：CPU/GPU 型号、可用 ffmpeg / GStreamer 版本、是否有硬件编码（转码 H.265→H.264 时需要）。
5. **Q5 车端网络**：上行带宽、到 `firebot.youdaozd.com:8890/udp` 的连通性（云端已完成端口预检）。
6. **Q6 部署形态**：媒体发布是否并入 vehicle-edge 生命周期（推荐独立 `firebot-media-publisher@{rgb,thermal}.service`，低权限用户、`Restart=on-failure`、不依赖 ROS/Bridge），以及安装路径约定。
7. **Q7 云端流登记**：001 流 ID 确认为 `firebot-vehicle-01-roof_rgb` / `firebot-vehicle-01-roof_thermal`；由云端 CC 在生产库登记还是由研发提供幂等登记脚本。

## 4. 回填后的定点实现范围（预案，不扩大）

- 车端：`firebot-media-publisher` 脚本 + systemd 模板（从 `/etc/firebot/media-secret.env` 读 token/passphrase，
  不进 argv/日志；`-c copy` 优先，H.265 或非 yuv420p 时转码；SRT `streamid=publish:<stream>:<vehicle_id>:<token>`）。
- 云端：幂等 StreamRegistry 登记脚本（仅 `firebot-vehicle-*`，拒绝合成命名空间与 R002）。
- 不改：媒体鉴权、VideoCard、MQTT、G1/G2 命令合同、R002。
