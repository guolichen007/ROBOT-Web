# G2：Web 指令 → 001 执行 → ROS 软件 → ACK 闭环（实施与发布）

基线：`feature/r001-g1-p2-rc` @ `9ba84fb`。本文件描述 G2 的代码语义、部署配置差异、
升级工件与回滚。生产 main 不直接修改；本功能在独立功能分支提交。

## 1. 语义（状态分级，绝不混用）

| 阶段 | 事实来源 | Command.lifecycle_status / 字段 |
| --- | --- | --- |
| API 已受理（HTTP 202） | Outbox 写入 | `QUEUED` —— **不是**执行成功 |
| 已发布 | 目标 Broker PUBACK | `PUBLISHED` + `published_at` —— 仅表示 Broker 收到 |
| 车端已收到 / 诊断完成 | 车端 ACK（`ack_source=vehicle`） | 诊断：`SUCCEEDED`；软件测试：`ACK_ACCEPTED`（`data.stage=RECEIVED`） |
| ROS 软件执行中/完成 | ROS `/…/feedback` → event `software_feedback` | `EXECUTING` → `SUCCEEDED` / `FAILED`（`ack_payload_json.software_feedback[]`） |
| 未收到车端回执 | Adapter 超时 | `PUBLISHED_UNCONFIRMED`（`ack_source=transport_timeout`，结果未知） |
| 车端确定未执行 | 车端拒绝码 | `ACK_REJECTED`：`EXPIRED`/`STALE_BOOT`/`WRONG_VEHICLE`/`NOT_AUTHORIZED`/`MODE_MISMATCH` |
| 真实底盘动作 | —— | 001 无实现路径：执行档不含 → API `EXECUTION_PROFILE_DENIED`；车端 `NO_HARDWARE` |

软件测试命令（`execution_mode=SOFTWARE_TEST`）不创建业务巡检任务、不要求地图合同、
不改写 `enabled`/`estop_active`/`supported_commands`；Web 标注 `SOFTWARE_TEST · NO_HARDWARE`。

## 2. 路由（单一 Outbox 认领者 + 多 Broker 客户端）

- Dispatcher 仍是唯一 Outbox 认领者（`FOR UPDATE SKIP LOCKED` 不变），按
  `VEHICLE_TRANSPORT_PROFILES` 选择客户端：`default`→原 mosquitto；
  `r001-independent-v1`→r001-broker（独立 platform 口令文件；与默认口令相同即拒绝启动）。
- 未知 profile / 无对应客户端 → `RoutingError`，进入退避重试并写 `last_error`，**绝不回退**原 Broker。
- 专属 Adapter 只下行 `VEHICLE_AGENT_TRANSPORT_PROFILE` 所属车辆；原 Adapter 收到 001 内部命令即拒绝。
- 三侧一致性：专属 Adapter 每 0.5s 上报配置指纹（`service:vehicle-agent-adapter:routing:<instance>`），
  API 门禁与 Dispatcher 发布前校验，不一致 → `ROUTING_CONFIG_MISMATCH` 拒绝。

## 3. 会话合同（车端独立校验）

- WireCommand 向后兼容扩展：`vehicle_id`、`target_boot_id`、`expires_at`、`mode`。
- 执行器每次 MQTT 连接生成新会话 UUID，随 live availability（dict）与 status 上报；
  Ingress 采纳为 `robot.boot_id`（`agent_state.boot_source=vehicle`）——车端只校验自己生成的 UUID。
  只读 Agent（不报 boot_id）沿用云端生成逻辑；从 exec 回退 readonly 时云端自动换新会话。
- 车端校验：结构 → 幂等（同 msg_id 重放原 ACK/反馈，落盘 10 分钟）→ 四字段齐全 →
  本车 → 当前会话 → 未过期且非明显超前（>5s）→ 授权档与模式一致。
- clean session + 不订阅 retained：重连后 Broker 不会投递上一会话命令。

## 4. 精确配置差异

云端（`g2.env`，root:600，示例见 `deploy/u-dao/r001-independent/g2.env.example`）：

```
G2_DOWNLINK_ENABLED=true
G2_DOWNLINK_ALLOWLIST=firebot-vehicle-01
G2_VEHICLE_TRANSPORT_PROFILES=firebot-vehicle-01=r001-independent-v1
G2_TRANSPORT_PROFILE_ADAPTERS=r001-independent-v1=r001-dedicated-adapter
G2_VEHICLE_EXECUTION_PROFILES=firebot-vehicle-01=ros-software-test
G2_R001_TRANSPORT_PROFILE=r001-independent-v1
G2_DISPATCHER_PROFILES_JSON=<runtime>/g2/dispatcher-broker-profiles.json
R001_NETWORK=u-dao-firebot-r001-prod_r001
```

- `api`、`command-dispatcher`：加载 overlay `compose.g2-dispatch.override.yml`
  （Dispatcher 加入 r001 网络，挂载 r001 口令/CA/描述文件）。
- `r001-adapter`：`compose.r001-independent.yml` 新增 G2 键（默认全 false/空）。
- 原 `vehicle-agent-adapter`、`mqtt-ingress`、mosquitto、002 资产：**零变更**。
- DB：无迁移；001 行保持 `enabled=false`、`capabilities=[]`、`estop_active=NULL`。

车端 001：

- 安装 `services/vehicle_agent_v1_exec`（与 readonly 同一 repo/venv，同批准 SHA）；
- `/etc/firebot/vehicle-agent-v1-exec/execution_grant.json`（root:firebot 0640，示例见 deploy 目录）；
- `firebot-ros-software-bridge.service`（系统 python3 + rospy，namespace `/firebot_001/software`）；
- `firebot-vehicle-agent-v1-exec.service`（`Conflicts=` readonly 单元；同 run-dir flock 互斥）。

## 5. 上线顺序（每步可独立回滚）

1. 云端：专属栈先更新（r001-adapter 带 G2 键）→ 心跳与配置指纹出现；
2. 云端：api + command-dispatcher 加 overlay 重建（`--no-deps`）；检查
   `service:command-dispatcher:broker-heartbeat:r001-independent-v1`；
3. 车端：启动 ROS 软件桥（现场软件节点已 READY）→ `systemctl stop readonly && start exec`；
4. 云端确认 `agent_state.boot_source=vehicle` → Web「车端诊断」Ping → 获取状态 → 获取遥测；
5. G2-B：软件启动 → ROS 软件巡检测试 → 停止软件巡检 → 软件停止。

## 6. 回滚

- 车端：`systemctl stop firebot-vehicle-agent-v1-exec && systemctl start firebot-vehicle-agent-v1-readonly`
  （回到零订阅；云端自动换新会话，旧命令全部失效）；删除 grant 文件即禁止 exec 启动。
- 云端：去掉 overlay 重新 `up -d --no-deps api command-dispatcher`；专属栈 G2 键置空后 `up -d r001-adapter`。
  全部 G2 键缺省即 fail-closed（零下行）。无 DB 回滚。

## 7. 验证证据（隔离环境，真实组件）

`integration/g2-command-loop-e2e`（REAL_E2E=1）：两个真实 Mosquitto（TLS/ACL/独立 platform 口令）、
真实 PostgreSQL 14 + Redis、真实 API/Outbox/Dispatcher/双 Adapter/双 Ingress 进程、真实 V1 执行器进程、
真实 ROS1 rosmaster + 软件桥 + 软件节点。覆盖：001 ping/状态/遥测闭环与 Broker 包级路由证据、重复命令
只执行一次、车端独立拒绝（旧会话/跨设备/过期/超前/未授权/模式不符）、重启新会话拒绝旧命令、ROS 软件
start/patrol/stop_patrol/close 反馈闭环与拒绝即失败、跨 Broker 误投拒绝、未知 profile 不回退、冻结车辆
无虚假 ACK 且恢复后过期拒绝、R002 快照不变。


## 8. G2-R1 修订（001 正式 ROS 接口 / 停止语义 / E2E 登录 / 审计）

- **001 正式接口**：契约随本分支版本化于 `integration/ros1/firebot-001-software/`
  （G2-INTERFACE.md、msg/、src/command_node.py）。软件桥直接使用
  `firebot_001_software/SoftwareCommand|SoftwareFeedback|SoftwareStatus`（`--message-package`
  可配置），不要求 001 停用现场节点；参考模拟节点已删除。
  - `SoftwareCommand.command_id` = V1 msg_id（UUID）；云端业务 command_id 只在云端关联
    （Command.payload_json.message_id），二者不混用。`params` 序列化为 JSON 字符串。
  - status 映射：ACCEPTED→ACCEPTED，RUNNING→EXECUTING，COMPLETED→COMPLETED，
    REJECTED→REJECTED（detail→reason_code：NOT_READY/ALREADY_RUNNING/ALREADY_STOPPED…），
    STOPPED→STOPPED（原始 ros_status 保留）；`software_test` 非 true → FAILED
    (SOFTWARE_TEST_FLAG_MISSING)。SoftwareStatus 逐字段转换为可序列化 dict。
  - 软件巡检参数：仅 SOFTWARE_TEST 模式接受 `{"rounds": N}`（1..1000）；真实巡检仍要求空参数。
- **停止语义**：001 节点对 stop_patrol 回 ACCEPTED（stop 自己的 id），巡检线程以 patrol 的 id
  发 STOPPED。桥把 STOPPED 交给 patrol（云端 patrol → `CANCELLED`，ack_reason=`STOPPED`，
  反馈序列保留），并为 stop 生成以 stop 自己 msg_id 关联的 `COMPLETED`（ros_status=STOPPED，
  `stopped_command_id`=patrol msg_id，云端回填 `stopped_cloud_command_id`）。
- **异步执行**：软件任务进入有界线程池（4）；命令工作线程只做校验/回执，诊断与 stop 不被长任务
  阻塞；启动类任务（start/close/patrol）互斥，冲突回 `BUSY`（确定未执行）；软件反馈超时从最后
  一次真实反馈起算。
- **E2E 登录**：G2 E2E 不再覆盖 `BOOTSTRAP_ADMIN_PASSWORD`（与 CI seed 的 admin 哈希不一致导致
  401），改为仅在隔离库（APP_ENV=test + REAL_E2E=1）创建/重置专用测试管理员 `g2-e2e-admin`；
  不触碰 bootstrap admin，不猜密码。
- **前端审计**：`apps/web/.npmrc` 指向 npmmirror，该镜像未实现 `/-/npm/v1/security/*`（404），
  导致 CI 审计“不可用→fail closed”。审计脚本对 audit 子命令显式使用官方 registry
  （`NPM_AUDIT_REGISTRY` 可覆盖），门禁判定（生产 Critical=0）不变。

车端升级（增量）：exec 单元不变；`firebot-ros-software-bridge.service` 改为 source 现场工作空间
`/home/tl/firebot_001_ws/devel/setup.bash`（`FIREBOT_ROS_WS_SETUP` 可覆盖）以导入
`firebot_001_software` 消息。


## 9. G2-R2 生产部署清单（五服务，统一 G2 批准 SHA）

| 服务 | 栈 / 项目名 | 镜像变量（g2.env） | 回滚值 |
| --- | --- | --- | --- |
| api | 主栈 `u-dao-firebot` + overlay | `G2_PYTHON_IMAGE=firebot-python:g2-<SHA>` | 去掉 overlay → 原 `FIREBOT_PYTHON_IMAGE` |
| command-dispatcher | 主栈 + overlay（加入 r001 网络） | `G2_PYTHON_IMAGE` | 同上 |
| web | 主栈 + overlay | `G2_WEB_IMAGE=firebot-web:g2-<SHA>` | 去掉 overlay → 原 `FIREBOT_WEB_IMAGE` |
| r001-adapter | `u-dao-firebot-r001-prod` | `R001_ADAPTER_IMAGE`，实例 `R001_ADAPTER_INSTANCE_ID=r001-dedicated-adapter-v2` | 不带 g2.env 重新 up（模板默认 `r001-dedicated-adapter`，下行全关） |
| r001-ingress | `u-dao-firebot-r001-prod` | `R001_INGRESS_IMAGE` | 同上 |

- **绝不**在 g2.env 设置 `FIREBOT_PYTHON_IMAGE`/`FIREBOT_WEB_IMAGE`：会改变 mosquitto 之外的 002
  链路服务（mqtt-ingress、vehicle-agent-adapter、task-worker…）展开配置并触发重建
  （`g2-verify-compose.py --baseline` 反证：非 G2 服务 image 变化 → FAIL）。
- **r001-ingress 必须与 api/dispatcher/r001-adapter 同 SHA**：软件反馈 `software_feedback`、
  STOPPED/CANCELLED、车端会话采纳由新版 ingress 处理；旧版 ingress 不得处理新版反馈。
- 实例 ID：`R001_ADAPTER_INSTANCE_ID` 与 `G2_TRANSPORT_PROFILE_ADAPTERS` 中实例名必须一致
  （核验脚本强制）；`-v2` 后缀使新实例心跳/路由指纹键与 G1 实例（`r001-dedicated-adapter`）隔离，
  回滚时旧实例键自然过期，不会被误读。

### 9.1 发布前核验（只读，生产主机；全部为强制项）

约定：`G1=<当前生产 G1 发布树>`（不动），`G2=<新解包的 G2 发布树>`，`R=/srv/u-dao/projects/firebot/runtime`，
`SHA=<完整 40 位 G2 SHA>`。基线必须用**当前生产发布树 + 当前 env 文件**渲染（真实 G1 配置），
不得用 G2 树去掉 overlay 代替——compose 的 build/volume 路径相对发布树，且 G2 模板新增了缺省键。

```bash
B="-p u-dao-firebot --profile vehicle-agent -f docker-compose.server.yml -f deploy/u-dao/compose.u-dao.yml"
GO="-f deploy/u-dao/r001-independent/compose.g2-dispatch.override.yml"
X="-f deploy/u-dao/r001-independent/compose.r001-independent.yml"
# 1) 真实 G1 基线（当前生产树 + 当前 env）
(cd $G1 && docker compose $B --env-file $R/server.env config --format json) > /tmp/g1-main.json
(cd $G1 && docker compose $X --env-file $R/r001.env config --format json) > /tmp/g1-r001.json
# 2) G2 目标配置
(cd $G2 && docker compose $B $GO --env-file $R/server.env --env-file $R/g2.env config --format json) > /tmp/g2-main.json
(cd $G2 && docker compose $X --env-file $R/r001.env --env-file $R/g2.env config --format json) > /tmp/g2-r001.json
# 3) 同树基线（消除发布树路径差异后判定“非 G2 服务零变化”）
(cd $G2 && docker compose $B --env-file $R/server.env config --format json) > /tmp/g2tree-main-before.json
(cd $G2 && docker compose $X --env-file $R/r001.env config --format json) > /tmp/g2tree-r001-before.json
python3 $G2/deploy/u-dao/r001-independent/g2-verify-compose.py /tmp/g2-main.json /tmp/g2-r001.json \
  --sha $SHA --baseline /tmp/g2tree-main-before.json --r001-baseline /tmp/g2tree-r001-before.json
# 必须 G2_COMPOSE_VERIFY=PASS；--baseline/--r001-baseline 缺失脚本直接拒绝运行
```

核验字段：五服务 image 均为 `:g2-<完整 40 位 SHA>`、无 latest、四个 Python 服务同镜像；api/dispatcher/
r001-adapter 的 5 个 G2 键逐字相同；r001-adapter `FIREBOT_SERVICE_INSTANCE_ID=r001-dedicated-adapter-v2`、
`VEHICLE_AGENT_TRANSPORT_PROFILE=r001-independent-v1`、allowlist 恰为 `firebot-vehicle-01`；原
vehicle-agent-adapter 无 allowlist；dispatcher networks ⊇ {firebot, r001} 且挂载 r001 口令与 broker
profiles；r001-broker `8884→8883` 且与基线逐字段一致；主 mosquitto `→8883`；两栈项目名不同；非 G2
主栈服务（mosquitto/mqtt-ingress/vehicle-agent-adapter/task-worker/migrate/…）与同树基线逐字段一致。

### 9.2 升级顺序（每步 healthy 后进入下一步；全程 `--no-deps`，不 `down`）

1. 预拉/导入镜像 `firebot-python:g2-$SHA`、`firebot-web:g2-$SHA`（禁止现场 build）。
2. 专属栈（先接收侧）：
   `(cd $G2 && docker compose $X --env-file $R/r001.env --env-file $R/g2.env up -d --no-deps r001-ingress r001-adapter)`
   → 核验 `service:mqtt-ingress:heartbeat:r001-dedicated-ingress`、
   `service:vehicle-agent-adapter:heartbeat:r001-dedicated-adapter-v2` 与路由指纹键存在。
3. `(cd $G2 && docker compose $B $GO --env-file $R/server.env --env-file $R/g2.env up -d --no-deps api command-dispatcher)`
   → 核验 `service:command-dispatcher:broker-heartbeat:r001-independent-v1`。
4. `(cd $G2 && docker compose $B $GO ... up -d --no-deps web)`。
5. 车端 001 升级（见交付包 README）；最后 Web Ping。

### 9.3 回滚顺序（逆序；必须回到真实 G1 配置，而非 G2 树的模板默认）

1. 车端：`systemctl stop firebot-vehicle-agent-v1-exec firebot-ros-software-bridge && systemctl start firebot-vehicle-agent-v1-readonly`。
2. 主栈：`(cd $G1 && docker compose $B --env-file $R/server.env up -d --no-deps api command-dispatcher web)`
3. 专属栈：`(cd $G1 && docker compose $X --env-file $R/r001.env up -d --no-deps r001-adapter r001-ingress)`
4. 回滚核验（只读）：
   ```bash
   (cd $G1 && docker compose $B --env-file $R/server.env config --format json) > /tmp/rb-main.json
   (cd $G1 && docker compose $X --env-file $R/r001.env config --format json) > /tmp/rb-r001.json
   python3 $G2/deploy/u-dao/r001-independent/g2-verify-compose.py rollback /tmp/rb-main.json /tmp/g1-main.json \
     api,command-dispatcher,web,mosquitto,mqtt-ingress,vehicle-agent-adapter
   python3 $G2/deploy/u-dao/r001-independent/g2-verify-compose.py rollback /tmp/rb-r001.json /tmp/g1-r001.json \
     r001-adapter,r001-ingress,r001-broker            # 两者必须 G2_ROLLBACK_VERIFY=PASS
   ```
5. 无 DB 迁移、无数据回滚；mosquitto(8883)、r001-broker(8884)、002 链路全程不重建。

反证（沙箱实测）：在 G2 树内“去掉 overlay/g2.env”渲染，与真实 G1 不一致（r001-adapter 多出 5 个
缺省 G2 键；主栈 build/volume 路径随发布树变化）→ `G2_ROLLBACK_VERIFY=FAIL`；按本节从 G1 树回滚 → PASS。
