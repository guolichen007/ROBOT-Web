# G2：Web 指令 → 001 执行 → ROS 软件 → ACK 闭环（实施与发布）

基线：`feature/r001-g1-p2-rc` @ `9ba84fb`。本文件描述 G2 的代码语义、部署配置差异、
升级工件与回滚。生产 main 不直接修改；本功能在独立功能分支提交。

## 1. 语义（状态分级，绝不混用）

| 阶段 | 事实来源 | Command.lifecycle_status / 字段 |
| --- | --- | --- |
| API 已受理（HTTP 202） | Outbox 写入 | `QUEUED` —— **不是**执行成功 |
| 已发布 | 目标 Broker PUBACK | `PUBLISHED` + `published_at` —— 仅表示 Broker 收到 |
| 车端已收到 / 诊断完成 | 车端 ACK（`ack_source=vehicle`） | 诊断：`SUCCEEDED`；软件测试：`ACK_ACCEPTED`（`data.stage=RECEIVED`） |
| ROS 软件执行中/完成 | ROS `/…/feedback` → event `software_feedback` | `EXECUTING` → `SUCCEEDED` / `FAILED`（`ack_payload_json.software_feedback[]`） |
| 未收到车端回执 | Adapter 超时 | `PUBLISHED_UNCONFIRMED`（`ack_source=transport_timeout`，结果未知） |
| 车端确定未执行 | 车端拒绝码 | `ACK_REJECTED`：`EXPIRED`/`STALE_BOOT`/`WRONG_VEHICLE`/`NOT_AUTHORIZED`/`MODE_MISMATCH` |
| 真实底盘动作 | —— | 001 无实现路径：执行档不含 → API `EXECUTION_PROFILE_DENIED`；车端 `NO_HARDWARE` |

软件测试命令（`execution_mode=SOFTWARE_TEST`）不创建业务巡检任务、不要求地图合同、
不改写 `enabled`/`estop_active`/`supported_commands`；Web 标注 `SOFTWARE_TEST · NO_HARDWARE`。

## 2. 路由（单一 Outbox 认领者 + 多 Broker 客户端）

- Dispatcher 仍是唯一 Outbox 认领者（`FOR UPDATE SKIP LOCKED` 不变），按
  `VEHICLE_TRANSPORT_PROFILES` 选择客户端：`default`→原 mosquitto；
  `r001-independent-v1`→r001-broker（独立 platform 口令文件；与默认口令相同即拒绝启动）。
- 未知 profile / 无对应客户端 → `RoutingError`，进入退避重试并写 `last_error`，**绝不回退**原 Broker。
- 专属 Adapter 只下行 `VEHICLE_AGENT_TRANSPORT_PROFILE` 所属车辆；原 Adapter 收到 001 内部命令即拒绝。
- 三侧一致性：专属 Adapter 每 0.5s 上报配置指纹（`service:vehicle-agent-adapter:routing:<instance>`），
  API 门禁与 Dispatcher 发布前校验，不一致 → `ROUTING_CONFIG_MISMATCH` 拒绝。

## 3. 会话合同（车端独立校验）

- WireCommand 向后兼容扩展：`vehicle_id`、`target_boot_id`、`expires_at`、`mode`。
- 执行器每次 MQTT 连接生成新会话 UUID，随 live availability（dict）与 status 上报；
  Ingress 采纳为 `robot.boot_id`（`agent_state.boot_source=vehicle`）——车端只校验自己生成的 UUID。
  只读 Agent（不报 boot_id）沿用云端生成逻辑；从 exec 回退 readonly 时云端自动换新会话。
- 车端校验：结构 → 幂等（同 msg_id 重放原 ACK/反馈，落盘 10 分钟）→ 四字段齐全 →
  本车 → 当前会话 → 未过期且非明显超前（>5s）→ 授权档与模式一致。
- clean session + 不订阅 retained：重连后 Broker 不会投递上一会话命令。

## 4. 精确配置差异

云端（`g2.env`，root:600，示例见 `deploy/u-dao/r001-independent/g2.env.example`）：

```
G2_DOWNLINK_ENABLED=true
G2_DOWNLINK_ALLOWLIST=firebot-vehicle-01
G2_VEHICLE_TRANSPORT_PROFILES=firebot-vehicle-01=r001-independent-v1
G2_TRANSPORT_PROFILE_ADAPTERS=r001-independent-v1=r001-dedicated-adapter
G2_VEHICLE_EXECUTION_PROFILES=firebot-vehicle-01=ros-software-test
G2_R001_TRANSPORT_PROFILE=r001-independent-v1
G2_DISPATCHER_PROFILES_JSON=<runtime>/g2/dispatcher-broker-profiles.json
R001_NETWORK=u-dao-firebot-r001-prod_r001
```

- `api`、`command-dispatcher`：加载 overlay `compose.g2-dispatch.override.yml`
  （Dispatcher 加入 r001 网络，挂载 r001 口令/CA/描述文件）。
- `r001-adapter`：`compose.r001-independent.yml` 新增 G2 键（默认全 false/空）。
- 原 `vehicle-agent-adapter`、`mqtt-ingress`、mosquitto、002 资产：**零变更**。
- DB：无迁移；001 行保持 `enabled=false`、`capabilities=[]`、`estop_active=NULL`。

车端 001：

- 安装 `services/vehicle_agent_v1_exec`（与 readonly 同一 repo/venv，同批准 SHA）；
- `/etc/firebot/vehicle-agent-v1-exec/execution_grant.json`（root:firebot 0640，示例见 deploy 目录）；
- `firebot-ros-software-bridge.service`（系统 python3 + rospy，namespace `/firebot_001/software`）；
- `firebot-vehicle-agent-v1-exec.service`（`Conflicts=` readonly 单元；同 run-dir flock 互斥）。

## 5. 上线顺序（每步可独立回滚）

1. 云端：专属栈先更新（r001-adapter 带 G2 键）→ 心跳与配置指纹出现；
2. 云端：api + command-dispatcher 加 overlay 重建（`--no-deps`）；检查
   `service:command-dispatcher:broker-heartbeat:r001-independent-v1`；
3. 车端：启动 ROS 软件桥（现场软件节点已 READY）→ `systemctl stop readonly && start exec`；
4. 云端确认 `agent_state.boot_source=vehicle` → Web「车端诊断」Ping → 获取状态 → 获取遥测；
5. G2-B：软件启动 → ROS 软件巡检测试 → 停止软件巡检 → 软件停止。

## 6. 回滚

- 车端：`systemctl stop firebot-vehicle-agent-v1-exec && systemctl start firebot-vehicle-agent-v1-readonly`
  （回到零订阅；云端自动换新会话，旧命令全部失效）；删除 grant 文件即禁止 exec 启动。
- 云端：去掉 overlay 重新 `up -d --no-deps api command-dispatcher`；专属栈 G2 键置空后 `up -d r001-adapter`。
  全部 G2 键缺省即 fail-closed（零下行）。无 DB 回滚。

真实 ROS1 rosmaster + 软件桥 + 软件节点。覆盖：001 ping/状态/遥测闭环与 Broker 包级路由证据、重复命令
