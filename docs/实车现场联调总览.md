## 4. 当前真实首车运行形态（Bridge-only 隔离）

当前首车现场**不是** `/opt` 默认安装形态，而是 `/home/tl/vehicle-bridge` + systemd Bridge-only 隔离运行：

```text
VEHICLE_OS=Ubuntu 20.04
BRIDGE_FIELD_PATH=/home/tl/vehicle-bridge
SYSTEMD_UNIT=/etc/systemd/system/firebot-bridge.service
WorkingDirectory=/home/tl/vehicle-bridge
ExecStart=/usr/bin/python3 -m firebot_bridge.main
ROS_MASTER_URI=http://127.0.0.1:1
Status=/run/firebot-bridge/status.json
Env=/etc/firebot/bridge.env
Secret=/etc/firebot/bridge-secret.env（不打印内容）
```

仓库自带 `/opt/install.sh` 标准部署路线**继续保留**为通用部署资产，但不再被描述成“当前这辆车正在使用”。

## 7. 数据 ownership 风险

```text
DUPLICATE_UPLINK_RISK=MEDIUM
```

原因：

1. CANONICAL_MQTT 与 `_platform/compat` 两路可影响同一车辆通道。
2. 缺少严格 per-channel ownership 仲裁。
3. 旧 ROS_COMPAT 一旦重新上行，可能把 profile/source_kind 拉回 ROS_COMPAT。

当前实时 CANONICAL_MQTT：`availability / heartbeat / capabilities / status / command_ack`
当前陈旧 ROS_COMPAT：`battery / odom / pose`
当前无：`smoke / bottom_ir / estop / roof_* / top_ir`

处理顺序：**先退役/隔离旧 compat 对应通道，最后才允许 source_kind migration**。
