# 车端云通信与视频链路（U-Dao 云方向）

## 1. 控制与遥测（MQTT）

- 车端 → 云端：MQTT 5 over TLS（8883），MQTT 用户名 == canonical vehicle_id 的 pattern ACL（只读自己 command、只写自己遥测；v1 命名空间同规则），`allow_anonymous=false`。
- 云端 → 车端：Command DB + Transactional Outbox + QoS1 + ACK + 幂等 + status convergence；MQTT5 Message Expiry Interval（`max(1,ceil(remaining))`）+ 车辆侧 payload `expires_at` 双校验 + boot_id 绑定 + UUID/fingerprint 去重。
- 高频遥测（location/heartbeat/sensor/status/availability）走 realtime 订阅（clean session，**无离线 backlog**）；业务事件（command_ack/task_status/alarm/event）走 durable 订阅（persistent session 600s 短时恢复）。
- manual 速度脉冲：QoS0 + 500ms TTL + 不排队不补发；**车端必须有本地 deadman/watchdog**（一段短时间无新鲜脉冲即本地停止）——云端不替代车辆本地安全停止。
- v1 车辆（agent_protocol=VEHICLE_AGENT_V1）：独立 topic 合同（cmd 1/ack 1/status 1+retain/telemetry 0/availability 1+retain/event 1），下行经 vehicle-agent-adapter 校验 binding/boot/expiry 后转发；`VEHICLE_AGENT_V1_DOWNLINK_ENABLED=false` 全程。
- 真实车辆接入前（OWNER_ACTION_REQUIRED）：per-robot MQTT credential + ACL、正式 MQTT 证书（不复用 bootstrap cert）、公网 8883 安全组。

## 2. 视频链（SRT → MediaMTX → WHEP/WebRTC）

```
Camera RTSP
    ↓
车端 FFmpeg / GStreamer（转封装，不转码要求见下）
    ↓ SRT（8890/udp；鉴权 token + 独立加密 passphrase）
U-Dao MediaMTX（authMethod http → /api/v1/media/authorize）
    ↓ WHEP / WebRTC（ICE 8189，端口保持）
Web HMI（VideoCard：用户主动连接 + 有界自动重连）
```

- **视频不走 MQTT**。MediaMTX 不是 transcoder。
- **codec 合同（V1 浏览器基准）**：H.264 + yuv420p。实车若只提供 H.265：在车端转码或单独评估浏览器兼容性，不得假定浏览器直接支持。
- **SRT 发布鉴权**：`streamid=publish:<path>:<user>:<pass>`（MediaMTX 将 user/password 映射进 authorize body；token 放 password 字段；JWT 因 SRT streamid 512 字符上限不适用，read 侧继续 WHEP+JWT 票据）。
- **SRT 加密**：独立 `SRT_PUBLISH_PASSPHRASE`（runtime secret，经渲染的 mediamtx runtime yml 注入），**与发布鉴权 token 严格分离、禁止复用**；公网 SRT 必须同时具备鉴权 credential + 加密 passphrase。
- **发布凭据**：bootstrap/synthetic V1 使用全局 media_publish_token；**真实多车公网接入前必须评估/实施 per-robot 或 per-stream 发布凭据**，不得把全局 static token 宣称为最终多车安全模型。
- **播放授权**：短时 media ticket（JWT，60s，user/robot/camera/stream 四重绑定，仅 Authorization 头）→ WHEP；Nginx `/media/` 透传 Authorization + `proxy_redirect / /media/`。
- **HLS fallback：DEFERRED（本轮明确不做）**。评估结论：浏览器原生 HLS 请求难以携带 Authorization 头、ticket 落入 URL/访问日志/referrer 的泄露风险、转封装与 auth 中间件改造复杂度远大于收益；后续如需 HLS，必须在不削弱媒体票据安全的前提下重新评估（hls.js xhrSetup 头注入等方案另立专项）。
- 合成验证：`deploy/u-dao/compose.media-e2e.yml`（RGB/thermal 双流 SRT 发布，H.264+yuv420p，测完即停）+ `scripts/check_srt_whep_e2e.py`（三态鉴权 + 双流隔离 + WHEP 201 + SDP answer 含 127.0.0.1:8189 ICE candidate）+ 浏览器 E2E（candidate-pair succeeded）。
